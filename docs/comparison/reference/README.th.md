เมื่อวัดด้วยเครื่องมือชุดเดียวกัน"** — ข้อความที่ไม่มีใครวัดผลของมัน คือคำแนะนำ

## วิธีการ

- **สามแขน ต่างกันทีละอย่าง**: (1) spec เปล่า · (2) spec + "ทบทวนงานตัวเอง
  หนึ่งรอบ" · (3) spec + `SKILL.md` + overlay + วน `gates_doctor.py` จนสะอาด
  · **แขนที่สองมีไว้แยกผลของ "การมีรอบที่สอง" ออกจากผลของเนื้อหา skill**
  ซึ่งการทดลองสองแขนแรกแยกไม่ออก (และตอบว่า ~3 ใน 4 ของช่องว่างบนแกน ASVS
  เป็นของรอบที่สอง ไม่ใช่ของ skill)
- **สิ่งที่ต้องคงที่**: โมเดล · ถ้อยคำของ spec · battery ที่ใช้วัด · การที่ agent
  ทุกตัวเป็น session ใหม่ที่ไม่เคยเห็น repo นี้ (ห้ามอ่านโค้ดของ todolist
  นอกจาก `SKILL.md` — ไม่งั้นวัดการลอก ไม่ใช่การทำตามกฎ)
- **N = 5 ต่อแขน (รวม 15 แอป)** — ผลของโมเดลภาษาไม่เท่ากันทุกครั้ง ตัวเลขเดี่ยว
  จึงไม่ใช่หลักฐาน (หลักเดียวกับ Phase 6: สิ่งที่ยืนยันได้คือรูปแบบที่ซ้ำ
  ไม่ใช่ค่าใดค่าหนึ่ง) · และ **N=5 ไม่มีการปฏิบัติทางสถิติใด ๆ** — สิ่งที่
  อ่านได้คือความสม่ำเสมอภายในแขน ไม่ใช่ระยะห่างของค่าเฉลี่ย

## battery ที่ใช้วัด — ชุดเดียวกันทุกแขน

1. **scan ของ overlay 8 ตัว** (`overlays/flask/checks/`) — กฎสากลของ repo นี้เอง
2. **ASVS probe 10 ข้อ** (`scripts/asvs_probe.py`) — ข้อที่พิสูจน์ได้จากตัวไฟล์
3. **semgrep `p/flask` + `p/python`** — แกนที่**ไม่ได้นิยามโดยเรา**

ตัวสั่งงานคือ `scripts/measure_generated.py` (รันเองได้ทุกเมื่อ — ดู docstring)
· path ของ semgrep ส่งด้วย `--semgrep` **ไม่ใช่ตัวแปรแวดล้อม** เพราะตัวรันที่มา
จาก env คือตัวรันที่เปลี่ยนได้โดยไม่มีใครเห็นในคำสั่ง (semgrep ของ repo นี้จับ
รูปนั้นเองตอนสคริปต์เข้ามาใหม่ — ด่านจับผู้เขียนด่านได้ ถือว่าทำงาน)

## กติกาที่ทำให้ตัวเลขนี้เชื่อได้ (และที่ทำให้มันเชื่อไม่ได้ถ้าละเลย)

- **เครื่องมือวัดถูกวัดก่อน** — `tests/test_asvs_probe.py` กางแอปคู่หนึ่ง
  (ละเมิดครบ / ทำครบ) แล้วบังคับว่า **ทุกข้อต้องแยกสองตัวนั้นออกจากกันได้**
  ข้อที่ตอบเหมือนกันทั้งสองแบบคือข้อที่ไม่ได้วัดอะไรเลย
- **probe ต้องไม่ผูกกับสำนวนเดียว** — ไม่งั้นมันวัด "เขียนเหมือนตัวอย่างของเราไหม"
  ซึ่งเอียงเข้าข้างฝั่งที่อ่าน skill ของเราโดยอัตโนมัติ · มี fixture สำนวนที่สอง
  บังคับไว้ (จับได้จริงสองจุดตอนวัดฝั่งควบคุมรอบแรก)
- **ตัดของที่ overlay ติดตั้งออกก่อนวัด** (`tools/`, `scaffold.json`, workflow
  ตั้งต้น) — นับโค้ดของเราเองให้แขนเดียวคือการบวกแต้ม ไม่ใช่การวัด
- **`na` ไม่ใช่ `ok`** — แอปเล็ก ๆ ไม่มี Dockerfile/workflow/ADR ให้ตรวจ
  ตัวสแกนพวกนั้นจึงไม่ได้ตัดสินอะไร รายงานแยกช่องเสมอ
- **ต้นไม้ที่วัดต้องมีแต่โค้ดของโปรเจกต์** (audit รอบ 18) — `NOT_OUR_CODE` ใน
  `asvs_probe.py` ตัด `.venv/` · `site-packages` · `node_modules` · `build/`
  ออกทั้งจากตัววัดและตัวนับบรรทัด · เงื่อนไขข้อนี้เคยเป็นแค่ความบังเอิญ
  (แอปที่ agent สร้างไม่พก virtualenv) จนกระทั่งยิง probe ใส่ repo นี้เอง
  แล้วพบว่า **4,171 จาก 4,299 ไฟล์ที่มันอ่านเป็นซอร์สของไลบรารี** และคำตอบ
  สามข้อพลิกด้วยหลักฐานของคนอื่น · ผลที่ตีพิมพ์ในหน้านี้ไม่กระทบ (แอปที่วัด
  มีไฟล์ python มากสุด 35 ไฟล์ต่อแอป) แต่ตอนนี้มีเทสต์กันแทนความบังเอิญแล้ว
- **บันทึกโมเดลกับวันที่คู่กับตัวเลข** — ผลขึ้นกับโมเดลและ prompt ซึ่งเปลี่ยน
  ใต้เท้า เคลมได้เฉพาะ "ในสภาพนั้น" (แบบเดียวกับที่ `docs/PERFORMANCE.md`
  บันทึกเครื่องที่วัด)

## สิ่งที่การทดลองนี้ **ไม่ได้** ตอบ

- ไม่ได้บอกว่าแอปที่ออกมา *ปลอดภัย* — probe ตอบว่า "มีร่องรอยของการป้องกันไหม"
  ไม่ใช่ "การป้องกันนั้นทำงานจริงไหม" (ไม่มีการรันแอปหรือยิงจริงในรอบนี้)
- ไม่ได้บอกว่ากฎข้อไหนของ `SKILL.md` มีผล — วัดเป็นชุด ไม่ได้แยกทีละข้อ
- ไม่ได้บอกว่าผลจะเหมือนเดิมกับโมเดลอื่นหรือ spec อื่น
